## 四组消融说明了什么

### 1 去反思：成功率 96% → 67%

没有反思，agent 出错后会**原样重试同一个动作**，直到触发"无进展"终止。

这正是第 17 讲说的：**反思的价值不在"想得更多"，而在"换一条路"**。

### 2 去记忆：步数 5.7 → 8.5，token 2333 → 4663

没有记忆，agent 只看得到最近几步，于是反复读已经读过的文件。

**成本翻倍，成功率还降到 75%**——因为它会"猜"自己读完了，然后给出错误答案。

### 3 去并行：步数 5.7 → 11.4

成功率不变，但步数翻倍。**并行工具不提升上限，只降低成本**——这是最纯粹的效率优化。

### 4 小模型：成功率 96% → 83%

错误率从 0.15 提到 0.35，成功率掉 13 个点。

对应第 17 讲的误差累积：单步可靠性下降，在 6 步任务上被放大。

## 三个关键点

### 为什么不用真的 LLM

调用 API 不可复现、不可离线、有成本。本实验把"模型"抽象成一个**带噪声的规则策略**：

```python
if self.rng.random() < self.cfg.error_rate:
    return [self.rng.choice(pool)]   # 犯错
```

这样错误率可控、结果可复现，消融的差异才看得清。

### 终止条件为什么要有四个

代码里只实现了三个：完成、无进展、步数上限。少任何一个都会出问题：

- 少了"无进展"：出错后死循环，烧钱；
- 少了"步数上限"：任务本身无解时永远跑；
- 少了"完成"：不知道什么时候停。

### 记忆为什么会降低成功率

反直觉：加了记忆反而"更慢但更准"，去掉记忆"更快但更错"。

因为没记忆的 agent 会在第 8 步"猜"自己读完了（`Action("finish", "guess")`），然后基于不完整信息作答。
