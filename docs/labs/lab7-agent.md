# Lab 7　Agent 与消融

!!! abstract "实验信息"
    **对应讲次**：[第 17 讲 Agent（一）](../05-应用层/l17-agent-1.md)、[第 18 讲 Agent（二）](../05-应用层/l18-agent-2.md)
    **耗时**：60–90 分钟　**硬件**：CPU　**依赖**：无（标准库）

## 目标

实现一个 ReAct agent，并用**消融**回答：记忆、反思、并行、模型能力，各值多少钱？

| # | 环节 | 实现 | 观察什么 |
|---|---|---|---|
| 1 | 环境 | 假仓库 + 三个工具 | 调用次数可统计 |
| 2 | 循环 | 思考 → 动作 → 观测 | 终止条件 |
| 3 | 记忆 | 已读文件集合 | 去掉会怎样 |
| 4 | 反思 | 出错后重新规划 | 去掉会死循环 |
| 5 | 并行 | 一次读多个文件 | 步数 vs 成本 |
| 6 | 消融 | 五组对比 | 每个机制值多少 |

## 运行

```bash
.venv/bin/python labs/lab7_agent/main.py
```

零依赖，一秒出结果。

## 实测结果

```
配置                 成功率   平均步数   平均 token   工具调用
baseline              96%     5.7       2333       9.9
去反思                 67%     5.6       2262       9.2
去记忆                 75%     8.5       4663      14.8
去并行                 96%    11.4       5016      10.8
小模型（错误率 0.35）      83%     6.2       2618      10.0
```

## 四组消融

### 1 去反思：96% → 67%

没有反思，出错后**原样重试**同一个动作，直到触发"无进展"终止。反思的价值不在"想得更多"，而在"换一条路"。

### 2 去记忆：步数 +50%，token 翻倍

只看最近 6 条历史 → 反复读已读文件；到第 8 步"猜"自己读完了，信息不全就作答。

**没有记忆不是"慢一点"，而是"不知道自己做没做完"**。

### 3 去并行：步数翻倍，成功率不变

并行是纯效率优化，不改变正确性——但步数翻倍意味着 token 翻倍，成本是真实的。

### 4 小模型：96% → 83%

错误率 0.15 → 0.35。单步可靠性的差距被 6 步任务放大，符合 $p^n$ 的规律。

## 为什么不用真 LLM

调用 API 不可复现、不可离线、有成本。本实验把"模型"抽象成**带噪声的规则策略**：

```python
if self.rng.random() < self.cfg.error_rate:
    return [self.rng.choice(pool)]   # 犯错
```

错误率可控、结果可复现，消融的差异才看得清。

## 思考题

1. `error_rate` 调到 0.5，哪组消融影响最大？
2. `max_steps` 降到 8，结果怎么变？
3. 给"去反思"加"重试上限 3 次"，成功率能恢复到多少？
4. 并行度从 3 提到 8，步数有下限吗？
