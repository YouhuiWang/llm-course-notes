## 三个结论

**1. LoRA 用 4.5% 的参数拿到 91% 的效果**（0.870 / 0.952）。

**2. 只训分类头会崩**（0.590）：任务 B 需要模型"看两个位置再比较"，而预训练学到的表示是"求和"，头部无法凭空造出这个能力。

**3. 适配哪一层比训多少参数更重要**：head 只有 130 个参数，但位置不对，等于没学。

## 关键实现

```python
class LoRALinear(nn.Module):
    def forward(self, x):
        return self.base(x) + (x @ self.A.t() @ self.B.t()) * self.scale
```

- `base` 冻结；
- `A` 随机初始化、`B` 零初始化（保证初始时等价于原模型）；
- `r=4` 时，一个 $128\times64$ 的矩阵只需 $4\times128+64\times4=768$ 个参数。

## 踩过的坑

**坑 1：任务不平衡**。第一版用"是否有重复元素"，8 个 0–9 的数几乎必然有重复，正类占 98%——三个配置全 0.974，看不出差异。换成"首元素 > 末元素"（约 50/50）才有区分度。

**坑 2：LoRA 加在注意力的 `out_proj` 上会崩**。`nn.MultiheadAttention` 内部依赖 `out_proj.weight` 的 fused 实现，替换成自定义层会报 `AttributeError`。本实验只给 FFN 加适配器。
