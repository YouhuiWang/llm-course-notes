## 四个关键点

### 1 为什么要先预分词

如果直接在整段文本上跑 BPE，跨词的组合（如 `的 发`）也会被合并，得到的 token 没有语义边界。

预分词（按空格、标点、中文字符切）保证合并只在词内发生。真实 tokenizer 用正则做更细的切分。

### 2 为什么按词频加权

统计相邻对时要乘以词的频次：

```python
for word, c in corpus.items():
    for a, b in zip(word, word[1:]):
        pairs[(a, b)] += c
```

不乘频次的话，"出现过一次的长词"会和"出现一千次的短词"权重相同，合并顺序就乱了。

### 3 编码为什么要按合并顺序

BPE 的合并有先后。编码时必须**优先应用最早的那条规则**：

```python
best = min(pairs, key=lambda p: rank.get(p, 10**9))
```

如果顺序错了，`the` 可能被拆成 `t` + `he`，而不是 `th` + `e`。

### 4 为什么对照 tiktoken 会差一倍

本实现 565 token，tiktoken 444 token。差距来自三处：

- **语料太小**：949 字符，学不出长合并；
- **预分词太粗**：tiktoken 用正则切得更细；
- **没有字节级回退**：真实 tokenizer 用 byte-level BPE，任何字符都能表示。
